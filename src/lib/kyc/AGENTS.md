# KYC engine rules (src/lib/kyc)
- Provider results are reduced to `universal_nullifier = BLAKE3(Poseidon256(canonical_id) || IDENTITY_HASH_PEPPER)` over the canonical ICAO/eIDAS anchors of `canonical-id.ts` (personal number first, then the document); Poseidon is the rout-zk x5_255_3 instance and `poseidon.test.ts` pins it to the Rust fixtures. Why: the same person yields the same value through every provider, and nothing stored can be turned back into a name or number.
- No name, document or personal number, date of birth, image or decision body is stored, logged or returned; the webhook re-fetches the decision from Didit and drops the body's `decision`, and anchor buffers are zero-filled in finally (JS strings cannot be wiped, so they are dropped right after reading). Why: zero-plaintext PII, and a forged webhook body can never define an identity.
- Didit webhooks are accepted only with a timing-safe HMAC-SHA256 over the raw bytes (X-Signature or X-Signature-Previous) inside a 300 s X-Timestamp window; the member comes only from the sealed `rk1.` vendor reference (`vendor-ref.ts`) and every write runs in that member's RLS context. Why: Didit never learns the member id and no caller can attest for someone else.
- The webhook consumes the session row last and every step before it is idempotent; transient failures answer 503 so Didit redelivers. Why: a crash between steps must not lose a paid verification.
- `rout_kyc_attest` (db-pending/0288) is the only write path into `verified_identity_nullifiers`; the engine uses it when `hasSchemaFeature("0288")` and otherwise relies on the UNIQUE `identity_verifications.unique_human_id`. Why: the code runs on 0286 today and gains cross-provider refusal once 0288 is live.
- DIDIT_API_KEY, DIDIT_WEBHOOK_SECRET, DIDIT_WORKFLOW_ID and IDENTITY_HASH_PEPPER are read per call in server-only modules and never get a VITE_ prefix. Why: least-privilege secrets.
- The Provider Discovery Hub lists providers from `providers.ts`; only entries with an `engine` can be started and their ids must exist in the 0288 provider CHECK (tested). Why: no button that does nothing, and the catalogue cannot drift from the database.
